# 04 模型与设置（`autocraft-routing`、`autocraft-settings`）

`autocraft-settings` 把提供方、模型偏好、MCP、项目级选择、聊天绑定和素材密钥存进一个 SQLite 数据库；`autocraft-routing` 把这些设置投影成每个引擎能用的路由，并在本机起一个模型网关。

## 1. 路由与命名

- 服务 trait 定义在 core：`ModelRouter`、`ProviderProbe`（`routing.rs`）、`ProviderService`、`ModelPrefService`（`provider.rs`）、`McpService`（`mcp.rs`）。
- 网关监听回环地址的随机端口，每个聊天一个令牌。
- 会话按路由签名判断是否需要重启；空闲会话签名变化时释放重建，运行中的会话延后到空闲。

| 项 | 名字 |
|---|---|
| 数据库 | `<data>/autocraft.db` |
| 路由名 | `autocraft-<id8>-<oc\|or\|am>` |
| 提供方密钥变量 | `AUTOCRAFT_PROVIDER_<ID8>_KEY` |
| 请求头变量 | `AUTOCRAFT_HDR_<ID8>_<n>` |
| MCP 变量 | `AUTOCRAFT_MCP_<ID8>_<E\|H><n>` |
| 用户 MCP 投影名 | `autocraft-<name>` |
| DSH 合并配置变量 | `AUTOCRAFT_DSH_MERGED_CONFIG` |

## 2. 数据库

`SCHEMA_VERSION = 7`（`settings/src/schema.rs`）。空库按版本建全部表；版本号更高的库拒绝打开（“请升级”），更低的开发版本库拒绝并提示删除 `autocraft.db` 重建。不自动删除或覆盖。

表：`providers`、`provider_endpoints`、`provider_models`、`provider_keys`、`model_prefs`、`hidden_models`、`mcp_servers`、`mcp_overrides`、`app_prefs`、`project_prefs`、`asset_keys`、`chat_bindings`、`builder_chats`。

## 3. 项目级选择

### 3.1 存储

```sql
CREATE TABLE project_prefs (
    project_id TEXT PRIMARY KEY,        -- ProjectId（规范化绝对路径）
    backend TEXT,         -- pi | omp | dsh；NULL = 跟随默认 Agent
    model_provider TEXT REFERENCES providers(id) ON DELETE SET NULL,
    model_id TEXT,        -- 与 model_provider 同时为 NULL 或同时非空（CHECK 约束）
    effort TEXT,          -- ThinkingLevel；NULL = 跟随
    mode TEXT NOT NULL,   -- clean_room | deep
    view TEXT,            -- 上次的主视图：project | workbench
    revision INTEGER NOT NULL
)
```

- 删除提供方时，触发器 `clear_project_models` 清空引用它的项目模型并递增 revision。
- 审批策略、提问方式、素材预算属于项目本身，存在 `craft.json`。这里只放引用本机提供方的选择（Agent、模型、强度、模式、视图），换一台机器就没有意义，所以不跟着项目文件夹走。
- 项目被删除时删除这一行，被复制时复制这一行。

### 3.2 服务

```rust
pub trait ProjectPrefService: Send + Sync {
    fn get(&self, project: &ProjectId) -> Result<ProjectPrefs>;
    fn set(&self, project: &ProjectId, change: ProjectPrefChange, expect_revision: u64) -> Result<ProjectPrefs>;
    fn remove(&self, project: &ProjectId) -> Result<()>;
    fn copy(&self, from: &ProjectId, to: &ProjectId) -> Result<()>;
}

pub struct ProjectPrefs {
    pub backend: Option<BackendKind>,
    pub model: Option<ModelRef>,
    pub effort: Option<ThinkingLevel>,
    pub mode: AnalysisMode,
    pub view: Option<MainViewPref>,
    pub revision: u64,
}

pub struct ProjectModelChoice {   // 新建项目时使用
    pub backend: Option<BackendKind>,
    pub model: Option<ModelRef>,
    pub effort: Option<ThinkingLevel>,
}
```

trait 定义在 `core/src/project.rs`，由 `autocraft-settings` 实现，与其他偏好共用数据库、写锁和 revision 规则。

### 3.3 解析规则

分析聊天、构建方会话、“只是问问”启动时都走 `autocraft_routing::resolve_project_route` 和 `prepare_project_route`（`routing/src/project.rs`）：

```text
backend = 已绑定的聊天 → binding.backend
          否则 project_prefs.backend → 否则 model_prefs.default_agent
          → 都没有：INVALID“请先在编码搭档中选择默认 Agent，或在项目设置中选择 Agent。”
model   = project_prefs.model → 否则 None（路由用全局 default_model）
effort  = project_prefs.effort → 否则 None（路由用全局 default_effort，并按模型夹紧）
```

- 已绑定的聊天恢复时 `new_session = false`；原生会话恢复后，引擎通过 `AgentSession::set_model` 应用当前的项目或全局模型。
- 项目选择的模型不能路由时返回 `INVALID`：“项目选择的模型「{名字}」不可用：{原因}。请前往项目设置。”。原因先取 `ModelRouter::model_status`（提供方已删除或停用、模型已删除或停用），否则取引擎限制（编码搭档选了官方配置、只允许某个提供方、选择的提供方不可用）。不自动换模型。
- 选择器里的模型来自 `ModelRouter::catalog(backend)`，列出的都是这个引擎能路由的。

### 3.4 签名与重启

项目选择改变后发 `AppEvent::Routing`；这个项目的空闲会话重新计算签名，必要时释放。运行中的复刻不受影响：构建方会话在运行开始时固定了模型，下一次运行生效。

## 4. 视觉能力

构建方能不能看图，取这次启动实际路由到的模型（`app/src/services/builder.rs`）：

- `EngineRouting.default_model` 有值：在 `providers` 里按路由名和模型 id 找到 `ProjectedModel`，`vision` 为真是 `Yes`，否则 `No`；
- 没有（引擎用自己的配置，例如编码搭档选了官方）：`Unknown`。

结果写进 `BriefCx.sees_pictures: SeesPictures { Yes, No, Unknown }`。`Unknown` 时 brief 的截图说明同时写两种做法，不猜测（见 [复刻编排](05-复刻编排.md)）。

## 5. 素材生成密钥

- 存储：`asset_keys (provider TEXT PRIMARY KEY, key TEXT NOT NULL, revision INTEGER NOT NULL)`。密钥明文存库，与提供方密钥一致；界面只显示掩码，复制时才读取明文。
- 注入：`AnalysisHub` 加载项目 `Engine` 时，把全部密钥组成 craft-anything 的 `AssetKeys` 放进 `session.ext`（`analysis/src/session.rs`）。已加载的 Engine 在下次加载时才拿到改动后的密钥。
- 不使用 `FAL_KEY` 环境变量回退，避免读到用户环境里的密钥。
- 设置入口：设置页“分析引擎”中的素材生成部分。

## 6. 设置页

| 页 | 内容 |
|---|---|
| 模型 | 默认模型、思考强度、上下文长度 |
| 分析引擎 | 新项目默认模式；Auto 模式；执行前询问；提问方式默认值；运行时研究（`runtime_study`）；外部引擎：Ghidra 目录、Java、内存、启动超时、引擎存储目录、一键安装；游戏引擎；构建：`good_enough`、`max_rounds`、网页对比宽度、最多页数、图片相似度门槛、并行数；素材生成：预算默认值、fal.ai 密钥 |
| 项目位置 | 新项目默认目录；额外的项目目录列表 |
| 提供方 | 提供方、端点、模型、密钥 |
| 编码搭档 | 一键安装固定版本的 pi、OMP、DSH；每个引擎的路由选择 |
| MCP | 用户 MCP 服务器，投影名 `autocraft-<name>` |
| 日志 | 日志查看 |
| 外观 | 主题 |
| 语言 | 简体中文 / English / 跟随系统（`app_prefs.locale`） |

“分析引擎”页的写入走 craft-anything 的 `Settings::save_to`（新版本文件只读、损坏文件备份为 `.broken`），成功后把新设置交给已加载的 Engine：插件配置变化且项目空闲时直接卸载，下次请求按新配置加载；其他情况在拿到锁时应用。
