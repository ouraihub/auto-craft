# 01 契约（`autocraft-core`）

`autocraft-core` 只放契约：领域类型、强类型 id、服务 trait、DTO、事件和错误码，不做 I/O、不依赖 UI。本文列出分析、项目、inbox、复刻相关的契约；会话的通用类型（`Message`、`ContentBlock`、`SessionSnapshot`、`SessionEvent`、`Interaction*`、`Capabilities`、`ModelInfo`、`SessionUsage`）和提供方 / 路由 / MCP 的类型以 `crates/core/src` 为准。

## 1. 强类型 id 与作用域

用 `id!` 宏定义：每个 id 都是 `#[serde(transparent)]` 的字符串 newtype，不同类型之间不能混用。

| id | 说明 |
|---|---|
| `ProjectId` | 项目根目录规范化后的绝对路径（Windows 去掉 `\\?\` 前缀，盘符大写），即一个 craft-anything 工作区（含 `craft.json` 的目录） |
| `ChatId` | 宿主生成的 UUID v4 |
| `NativeSessionKey` | 引擎的原生 locator，对宿主不透明 |
| `EvidenceId` | craft-anything 的证据 id（`ev_` 加 SHA-256 前缀），原样透传 |
| `InboxRequestId` | craft-anything inbox 请求 id，原样透传 |
| `TargetId` | craft-anything `TargetId` 的字符串形式 |
| `NoteId` | 复刻运行中补充说明的 id；进程内单调递增，序列化为十进制字符串 |

终端按调用者传入的规范化绝对 `cwd` 分组，运行句柄直接用 `uuid::Uuid`。设置页在没有项目时只管理全局 MCP。

一次引擎启动的作用域：

```rust
/// 一次引擎启动能访问的范围：哪个项目、哪个聊天。令牌只映射到它。
pub struct ChatScope {
    pub project: ProjectId,
    pub chat: ChatId,
    pub purpose: ChatPurpose,
}

pub enum ChatPurpose {
    /// 分析聊天：用户和 Agent 对话。
    Analysis,
    /// 复刻构建方会话：权限请求走审批策略，见 05 §4。
    Builder,
    /// “只是问问”：只读会话，见 05 §8。
    Question,
}
```

### 3.3 `BuilderHooks`

复刻构建方会话需要宿主对每个写文件、执行命令、访问网络的动作做策略判定（05 §4）。引擎适配器在收到这类动作时调用它，同步拿到结果：

```rust
pub trait ActionPolicy: Send + Sync {
    /// 阻塞直到有结论：策略直接放行或拒绝，或者用户在卡片上回答。`cancel` 置位时返回 `Refuse`。
    fn decide(&self, action: &AgentAction, cancel: &CancelFlag) -> PolicyVerdict;
}

/// 引擎动作的统一形状。适配器负责从各自协议翻译过来（03 §6）。
pub enum AgentAction {
    WriteFile { path: String },
    RunCommand { command: String, shell: Shell },
    ReadFile { path: String },
    WebFetch { url: String },
    WebSearch { query: String },
    /// 无法归类的工具，按名字询问。
    Other { tool: String, input: serde_json::Value },
}

pub enum Shell { Bash, PowerShell }

pub enum PolicyVerdict {
    Allow,
    /// 原因原样告诉构建方，让它换一种做法。
    Refuse { reason: String },
}

#[derive(Clone)]
pub struct BuilderHooks {
    pub policy: Arc<dyn ActionPolicy>,
}
```

`CancelFlag` 是 core 里的一个 `Arc<AtomicBool>` 包装，有 `is_cancelled()` 方法，不依赖 craft-anything 的 `CancelToken`。

### 3.4 `AgentSession::steer`

```rust
pub trait AgentSession: Send + Sync {
    // ……其他方法……

    /// 运行中插话：引擎在下一个工具调用之后读到这段文字，不打断当前这一轮。
    /// 空闲时等同于 prompt。不支持的引擎返回 INVALID，调用方退回“本轮结束后再发”。
    fn steer(&self, text: &str) -> Result<()> {

    }
}
```

`Capabilities.steer: bool` 表示引擎是否支持运行中插话，三个引擎的取值见 03 §7。

### 4.4 `RebuildService`

```rust
pub trait RebuildService: Send + Sync {
    /// 开始或继续一次复刻运行。超过并行上限时排队，返回 Queued{position}。
    fn start(&self, project: &ProjectId, request: RunRequest) -> Result<RunStarted>;
    fn stop(&self, project: &ProjectId) -> Result<()>;
    /// 运行中补充说明；没有运行时返回 INVALID，调用方改用 start(follow-up)。
    fn note(&self, project: &ProjectId, text: &str, pictures: Vec<PathBuf>) -> Result<NoteId>;
    /// 撤回还没被构建方读到的说明；已读返回 Ok(None)。
    fn withdraw(&self, project: &ProjectId, id: &NoteId) -> Result<Option<String>>;
    fn status(&self, project: &ProjectId) -> Result<RunStatus>;
    /// 构建方自查：把请求交给运行中的复刻并等待报告（05 §10.3）。没有运行时返回 INVALID。
    fn self_check(&self, project: &ProjectId, wait: Duration, cancel: &CancelFlag) -> Result<String>;
    /// “只是问问”：阻塞直到回答，最多 10 分钟（05 §8）。
    fn ask(&self, project: &ProjectId, question: &str, cancel: &CancelFlag) -> Result<Answered>;
    /// 标记为完成（project_build_finish）。运行中返回 BUSY。
    fn finish(&self, project: &ProjectId) -> Result<()>;
    /// 预览地址（网站）；没有构建结果时返回 NOT_FOUND。
    fn preview(&self, project: &ProjectId) -> Result<String>;
    /// 运行游戏或应用的构建结果（project_play）。
    fn play(&self, project: &ProjectId) -> Result<()>;
    /// 活动日志的一段（最新在后）。
    fn activity(&self, project: &ProjectId, offset: usize, limit: usize) -> Result<Vec<ActivityLine>>;
```

## 5. 错误

`Error` 带一个稳定的 code（`ErrorCode`），完整列表见 [错误日志与测试](07-错误日志与测试.md)。和分析相关的几个：

| code | 含义 | 典型来源 |
|---|---|---|
| `TOOL_FAILED` | 分析工具失败；`context` 是转换后的中文说明，附带工具原文的修复建议 | `AnalysisService::call` |
| `CONSENT_REQUIRED` | 需要确认的工具没有得到同意（用户拒绝，或没有 inbox） | 同上 |
| `DEEP_REQUIRED` | 净室模式拒绝了这个工具 | 同上 |
| `ENGINE_MISSING` | 外部引擎（Ghidra、adb……）没装 | 同上 |
| `READ_ONLY` | 项目由更新版本写入，只读 | `ProjectService`、`RebuildService` |

craft-anything `ErrorCode` 到 autocraft 错误码的映射在 02-分析服务 §8。错误的 `context` 不得包含证据正文、工具参数、目标文件内容。
