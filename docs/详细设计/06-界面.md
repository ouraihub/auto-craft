# 06 界面（`autocraft` app、`autocraft-ui`）

视觉令牌、尺寸、字体、组件和 GPUI 实践由 `autocraft-ui` 统一提供。本文规定 autocraft 的视图结构、每个视图的数据来源和交互。所有界面文字都走 i18n key（§10），下文出现的中文是 `zh-CN` 的取值。

## 1. 视图树

```text
Workbench（窗口根，Entity）
├─ TopBar       品牌 · 项目选择器 · 目标选择器 · [项目|工作台] · 净室/深度 · Agent·模型 · 用量 · ⚙
├─ Notice      错误通知条（带复制 TraceId）
├─ ActivityBar         首页 · 项目 · 列表栏 · 证据 · 任务 · 设置
├─ Main（按 MainView 切换）
│  ├─ HomeView          首页 / Make
│  ├─ ProjectView       项目视图（复刻与简单模式）
│  └─ WorkbenchView     工作台（逆向）
├─ StatusLine          引擎占用 · 进度 · 任务数 · 排队
└─ 覆盖层       CommandPalette · SettingsDialog · ConfirmDialog
```

```rust
pub enum MainView { Home, Project, Workbench }
```

- `Workbench` 持有 `main: MainView` 和当前项目 `project: Option<ProjectId>`。`Home` 不需要项目；`Project` 和 `Workbench` 需要，没有项目时回到 `Home`。
- 切换项目时，恢复该项目上次的视图（`project_prefs.view`，见[模型与设置](04-模型与设置.md)），没有记录时：有复刻请求的项目进 `Project`，`LookInside` 项目进 `Workbench`。
- 每个视图是一个 `Entity`，切换视图时不销毁另外两个，保留各自的滚动位置和输入。

## 2. 状态与事件

```rust
pub struct AppState {
    pub services: Services,
    pub projects: Vec<ProjectSummary>,
    pub project: Option<ProjectId>,
    pub notice: Option<Notice>,
}

pub enum AppEvent {
    Projects,     // 项目列表变化
    Project,      // 当前项目变化
    Routing,      // 提供方、MCP、模型偏好、项目模型选择变化
    Analysis(ProjectId),    // 目标、证据、未知项、模式变化（见 02-分析服务）
    Inbox(ProjectId),       // 卡片新增或撤回
}
```

后台事件的通道（在 `services.rs` 的 `Channels` 里），由 `Workbench` 的前台任务泵入：

| 通道 | 内容 | 去向 |
|---|---|---|
| `sessions` | 分析聊天的 `SessionEvent` | `AgentPanel` |
| `rebuild` | `RebuildEvent` | `ProjectView`（feed）、`TopBar`（状态）、`ProjectsPanel`（状态点） |
| `analysis` | `AnalysisChanged`、`AnalysisProgress` | `WorkbenchView`、`StatusLine` |
| `inbox` | `InboxNotice`、`InboxWithdrawn` | `ProjectView`、`AgentPanel`、`ProjectsPanel`（"需要你"） |
| `terminals` | 终端输出 | `TerminalPanel` |

所有服务调用都经 `state::run`，带代际号，过期的结果丢弃。

## 3. 顶栏

| 元素 | 数据 | 交互 |
|---|---|---|
| 品牌 | — | 点击回首页 |
| 项目选择器 | `AppState.projects` | 下拉：最近项目、全部项目、新建 |
| 目标选择器 | `AnalysisView.targets`、`active` | 切换目标调用 `core_target_select`；"打开目标…"调用 `core_target_open`（文件选择器） |
| 视图切换 | `MainView` | `ChoiceMenu` 下拉：项目 / 工作台；不在这两个视图时显示"视图"；没有项目时禁用 |
| 净室 / 深度 | `ProjectDetail.mode` | `ChoiceMenu` 下拉；选深度先在顶栏确认（见[分析服务](02-分析服务.md)），再选当前值不触发切换；复刻运行中禁用并提示原因 |
| Agent · 模型 | `project_prefs` 与当前聊天的 `SessionSnapshot.model` | 打开模型选择器（gpui-kit `Picker`），选择写入项目级选择（见[模型与设置](04-模型与设置.md)）；聊天里临时切换在聊天头部做 |
| 用量 | 当前项目 `usage.json` | 悬停显示 token、费用、时长，样式用 gpui-kit `ContextStatusView` |
| 设置 | — | 打开 `SettingsDialog` |

顶栏就是窗口标题栏，支持拖动与贴靠。

## 4. 首页（HomeView）

三扇门用当前值下拉切换；净室 / 深度在"分析方式"下拉中选择，下方说明随当前值变化：

### 4.1 做我自己的版本

| 字段 | 控件 | 绑定 |
|---|---|---|
| 目标类型 | 单选下拉：网站 / 应用 / 游戏 / 无 | `TargetRefDto` 的种类 |
| 地址或文件 | 输入框；应用和游戏旁边有"选择…"按钮（文件或文件夹选择器） | `TargetRefDto` |
| 模式 | 两张卡片：净室 / 深度，各带一句说明 | `NewProject.mode`，默认净室 |
| 要求 | 多行输入，支持粘贴图片（存进 `reference/`） | `NewProject.request` |
| 构建方 | 下拉：pi / OMP / DSH，未安装的灰显并带"去安装" | `ProjectModelChoice.backend` |
| 模型 | 模型选择器，第一项"跟随默认（{名字}）" | `ProjectModelChoice.model`、`effort` |
| 游戏：用什么做 | 下拉：自动选择 / Unity / Unreal / Godot / Rust，未安装的灰显 | 写进 request 的技术栈名 |
| 游戏：生成素材 | 开关 + 预算 | `PersonChange::GenerateAssets` |
| 保存位置 | 默认项目目录，"更改…" | `NewProject.folder` |
| 开始 | 主按钮 | `ProjectService::create` → `RebuildService::start` → 切到 `ProjectView` |

所选文件夹里已有文件时，弹出"已有文件"的三个选项（合并 / 另存 / 取消）。

### 4.2 改我的项目

选一个文件夹，写要求，选构建方和模型，开始。`Door::WorkOnMine`。

### 4.3 只看里面

选文件或填地址，开始：创建项目（`Door::LookInside`、默认深度）→ 打开目标并分诊 → 切到 `WorkbenchView`，右侧 Agent 页签自动开一个分析聊天，第一条消息由用户输入。

### 4.4 项目列表

首页下方是项目网格（`ProjectSummary`），每张卡片显示名称、目标、状态点（需要你 / 运行中 / 就绪 / 已暂停 / 中断）、更新时间；右键菜单：打开文件夹、重命名、复制、删除。

│ FeedItem 卡片     │ ProjectSidebar     │
├─ 计划条（可拖动分隔）─────────────────────────┤      │
├─ 输入区 ──────────────────────────────────────┤      │

### 5.1 feed

数据：`RebuildService::read_feed` 返回 Continuity 已折叠的权威 feed（运行中包含流式内容）；`RebuildEvent` 仅使快照失效并经现有 loading / reload_again 合并刷新。UI 不自行按 SessionEvent / Delta 建立第二套消息索引或拼接正文。尚未进入 feed 的分析 inbox 请求按 id 临时补入；权威请求出现后复用同一行并纠正来源，不重复卡片。

| FeedItem | 卡片 |
|---|---|
| `User` | 用户气泡，带图片缩略图 |
| `Step` | 一行，左侧图标对应 研究/构建/检查/就绪 |
| `Agent` | 构建方文字，Markdown（§8.3），流式时尾部光标 |
| `Work` | 折叠组："用了 N 个工具"，展开列出工具名和成败 |
| `Ask` | `AskCard` / `ApproveCard`（§8.2） |
| `Check` | `CheckCard`：相似度、通过的声明数、未比较的项、截图缩略图（点开看原图与对比） |
| `Error` | 错误卡：说明 + 修复建议 + "查看日志" |
| `Paused` | 一行"已暂停"+"继续"按钮 |
| `Plan` | 不进 feed，显示在计划条 |

列表按 `FeedItem` 下标复用卡片 Entity，流式输出只更新最后一个 `Agent` 卡片。

### 5.2 计划条

显示最新的 `Plan`（`feed::plan_shown`），每步一行 Todo/Doing/Done/Stopped。可以折叠（`project_plan_fold`）。

### 5.3 输入区

- `ChoiceMenu` 下拉：修改 / 只是问问。修改：运行中时调用 `note`，否则 `start(message)`；只是问问：调用 `ask`。
- 附图、粘贴图片（存进 `attachments/`）。
- 运行中时显示"待读的说明"列表，每条带"撤回"（`withdraw`），已读的消失。
- `/` 命令：输入以 `/` 开头时显示"插入命令"下拉，选中项填入输入框：`/approvals <类别> <allow|ask|refuse|default>`、`/btw <问题>`（等同"只是问问"）、`/stop`、`/continue`、`/done`。

### 5.4 右栏（ProjectSidebar）

| 区块 | 内容 | 动作 |
|---|---|---|
| 名称与状态 | `ProjectSummary.name`、`status`、`note` | 重命名 |
| 步骤 | `StepTracker`：研究 → 构建 → 检查 → 就绪，当前步骤高亮 | — |
| 结果 | 网站：预览；应用/游戏：运行 | `preview` / `play` |
| 构建方与模型 | `project_prefs` | 打开选择器；运行中修改提示"下次运行生效" |
| 审批策略 | 7 个类别各一行当前策略下拉：默认 / 允许 / 询问 / 拒绝；默认的实际取值放在提示中 | `PersonChange::Approval` |
| 提问方式 | 单选下拉：询问我 / 自己决定 / 默认 | `PersonChange::Questions` |
| 素材 | 开关、预算、已花费 | `PersonChange::*` |
| 文件 | 打开项目文件夹 / 打开 app 文件夹 | 系统文件管理器 |
| 管理 | 复制、删除 | 删除前确认，运行中禁用 |

## 6. 工作台（WorkbenchView）

```text
┌ 列表栏 200–520 ┬ 编辑区（页签条 28）──────────────┬ 右侧栏 320–560 ─┐
│         │       │ [Agent][检查器]  │
│         │       │ [证据][未知项]   │
│         ├ 底部面板（可折叠）[任务][日志][终端]┤           │
└────────────────┴───────────────────────────────────┴──────────────────┘
```

布局用 gpui-kit 的 `h_resizable` / `v_resizable`。

### 6.1 列表栏

| 种类 | 工具（第一个注册且可用的） | 何时出现 |
|---|---|---|
| 函数 | `native_functions_list` | 原生程序 |
| 字符串 | `native_strings_browse` | 原生程序 |
| 导入 | `native_named_addresses_list` | 原生程序 |
| 节 | `native_sections_list` | 原生程序 |
| 类 | `managed_members_list` / `java_classes_find` / `android_classes_find` / `apple_objc_classes_list` | .NET / Java / Android / Mach-O |
| 模块 | `js_app_map` | JS / Electron |
| 资源 | `native_pe_resources_list` | PE |

- 用 gpui-kit `DataTable` + `TableDelegate`，列：地址、名称、大小（按工具返回的字段）；按列排序在宿主内存里做。
- 顶部过滤框，按名称和地址子串过滤。
- 分页：工具都支持 `offset` / `limit`，滚动到底部时取下一页，每页 500 行。
- 点一行：记为选中（`selection`），右侧切到"检查器"，编辑区当前页签用这一行重新取数。

### 6.2 编辑区页签

| 页签 | 工具 | 渲染 |
|---|---|---|
| 伪 C | `native_function_pseudocode` | `CodeView`，C 语法高亮 |
| 反汇编 | `native_function_disassemble` | `CodeView`，地址列可点击跳转 |
| Hex | `native_bytes_show`（本地字节时直接读 `TargetInfo` 不调工具） | `HexView` |
| 调用图 | `native_call_graph_show` | `CallGraphView`，分层布局画在 canvas 上（§6.5） |
| 源码 | `js_sources_restore` | `CodeView`，JS 高亮 |
| 网络 | `web_page_watch` | `DataTable` |
| 结果 | 命令面板执行的工具 | `EvidenceCard` 或 JSON 树 |

- 参数只传工具 schema 里有的键：`offset`、`limit`、`address` / `function`、`name` / `module` / `path`、`input_path`。
- 每个页签的状态：

  ```rust
  pub enum Fill { Idle, Loading, Unavailable(String), DeepNeeded, EngineMissing { engine: String, fix: String },
      Error { message: String, fix: Option<String> }, Ready(ToolReply) }
  ```

  `DeepNeeded` 显示占位："这个视图需要深度模式"+"切换到深度"按钮。
- 页签顶部横幅：置信度标签、摘要、来源工具、证据 id（点开右侧"证据"）。

### 6.3 右侧栏

| 页签 | 内容 |
|---|---|
| Agent | 分析聊天（§7） |
| 检查器 | 当前选中行的 JSON 字段，按键值显示 |
| 证据 | `AnalysisView.ledger`，点开显示 `EvidenceCard`（取 `AnalysisService::evidence`） |
| 未知项 | `AnalysisView.unknowns`，按严重程度排序 |

### 6.4 底部面板

| 页签 | 内容 |
|---|---|
| 任务 | 进行中和已完成的工具调用（界面发起的、Agent 发起的），带进度和取消 |
| 日志 | 日志页的精简版，只显示本项目相关的行 |
| 终端 | `TerminalPanel`，工作目录为项目根目录 |

### 6.5 高亮与调用图

- 伪 C 用 C 语法高亮（gpui-kit 的 `tree-sitter-c` 特性，在 `autocraft-ui` 的 `gpui-kit` 依赖里打开），源码页用 JS 高亮（`tree-sitter-javascript`）；反汇编按助记符、寄存器、立即数、地址做简单的词法着色，不依赖 tree-sitter。
- 调用图（`autocraft-ui` 的 `CallGraphView`）从 `native_call_graph_show` 的结构化节点和边取数，自己做分层布局画在 GPUI `canvas` 上：从当前函数出发按调用深度分层（调用者在上、被调用者在下，各最多 3 层、每层最多 40 个节点，其余折叠），层内按名字排序再按相邻层重心排序减少交叉。节点是圆角矩形（函数名 + 地址），支持拖动平移、滚轮缩放。单击节点在列表栏选中该函数并打开伪 C，双击以它为中心重新取调用图；超过 500 个节点时不画图，提示改用文本页签。

## 7. Agent 面板（AgentPanel）

- 页签条、消息流、交互卡、输入框、模型选择器、用量。
- 作用域是项目：页签列表是这个项目的聊天（`chat_bindings` 按项目 id 过滤）。
- 同一个 Agent 面板实例在项目视图和工作台都能出现：项目视图里放在右栏底部的抽屉，工作台里是右侧栏的 Agent 页签。两处显示同一个 Entity，所以会话不会因为切换视图中断。
- 构建方会话可以只读查看：页签条最右的"构建方"页签，不能输入（构建方由复刻编排驱动）。
- 工具卡：分析工具的结果带证据 id 时显示 `EvidenceCard` 摘要，点开跳到工作台"证据"页签；其他工具保持折叠 JSON 卡。

## 9. 命令面板

- `Ctrl+K` 打开，用 gpui-kit `command` 模块（`Command`、`CommandItem`、`CommandState`）。
- 条目：应用命令（打开文件、打开文件夹、切换视图、切换模式、设置、导出报告、首页）+ 当前项目的全部工具（`AnalysisService::tools`）。
- 工具按 `toolset` 分组，按标题模糊匹配；不可用的工具灰显并显示原因（需要深度 / 缺引擎 / 需要目标）。
- 选中一个工具：按 `input_schema` 生成参数表单（string / number / integer / boolean / enum / 数组逗号分隔；必填项标星），执行后结果显示在"结果"页签。
- 带 `needs_consent` 的工具，执行前弹确认（界面执行时 `consented = true`，确认就是同意）。
- **导出报告**：把当前项目的调查记忆和证据摘要导出为 Markdown。

## 10. 多语言

- 用 `rust-i18n`，词条在 `crates/app/locales/ui.yml`，按语义 key 组织，切换后 `cx.refresh_windows()`。`zh-CN` 是完整语言，`en` 为补充；伪语言 `en-XA` 由 `PseudoBackend` 生成用于布局检查。
- key 前缀：`app.shell.*`、`app.home.*`、`app.project.*`、`app.workbench.*`、`app.agent.*`、`app.cards.*`、`app.settings.*`、`app.errors.<CODE>`、`tool.<id>.title`。
- 工具标题：`tool.<id>.title` 在 `zh-CN` 里给出译文，没有译文时显示原文。
- 术语：Clean room → 净室，Deep → 深度，Evidence → 证据，Functions → 函数，Strings → 字符串。
- 不翻译：工具 id、证据内容、Agent 回复、提示词、技能、日志、模型名、提供方名、协议 id、力度 wire id。
- 共享模型选择器、用量状态和密钥控件通过各 crate 的 `localization::set_translator` 注入宿主翻译；默认中文保留给其他宿主。`i18n::apply` 在 UI 线程切换回调后刷新窗口，已打开的模型搜索提示和缓存力度标签同步更新。

### 选择控件的信息密度

- 单选一律优先用当前值 + 下拉箭头（`autocraft_ui::components::ChoiceMenu`，或同样外观的菜单按钮），两项也不例外；复用 GPUI 菜单的选中态、键盘与焦点，不平铺候选值。`ChoiceMenu` 再选当前值不调用处理函数，切换型处理（如净室 / 深度）只在真实变化时运行。
- 已用下拉：首页三扇门、分析方式（净室 / 深度）、目标类型、构建方；顶栏视图切换与分析方式；项目侧栏分析方式；输入区修改 / 只是问问与"插入命令"；设置页的语言、分析提问方式、主题模式与对比度、日志级别、上下文窗口预设、MCP 传输协议、服务商直连 / 网关。
- 保留平铺的只有三类：工作台编辑页签和侧栏页签（导航，不是取值）；审批允许 / 拒绝与安装、运行、发送等动作按钮；多选（模型能力等复选框）与实体列表（服务商、项目）。布尔设置使用开关。
