# 07 错误、日志、测试

## 1. 错误

### 1.1 错误码一览

`autocraft-core` 的 `ErrorKind` 对应下列 code（`error.rs`）：

| code | 典型来源 | 界面处理 |
|---|---|---|
| `NOT_FOUND` | 项目、目标、证据不存在 | 通知 |
| `INVALID` | 参数、项目模型不可路由、请求描述不清 | 通知，附修复建议 |
| `CONFLICT` | `project_prefs` revision 过期、`StaleRevision` | 重新读取后重试 |
| `BUSY` | 运行中删除项目、运行中切换模式 | 通知并说明原因 |
| `CORRUPT` | 数据库损坏、证据哈希不符 | 通知，不改动数据 |
| `FORBIDDEN` | 操作系统拒绝 | 通知 |
| `TIMEOUT` | 握手 30 秒、只是问问 10 分钟、自查 30 分钟 | 通知 |
| `EXTERNAL` | 外部程序失败、引擎上游失败 | 通知 |
| `BACKEND_UNAVAILABLE` | Agent 无法启动 | 引导去编码搭档 |
| `PROTOCOL` | Agent 协议违约 | 通知 + 复制诊断 |
| `SESSION_CLOSED` | 会话已关闭 | 页签 / 卡片提示重新开始 |
| `SESSION_BUSY` | 会话正在运行 | 等待或提示占用 |
| `INTERACTION_EXPIRED` | 该请求已不再等待回答 | 卡片收起 |
| `TOOL_FAILED` | 分析工具失败 | 在页签 / 卡片里显示，附修复建议 |
| `CONSENT_REQUIRED` | 拒绝了执行确认 | 页签显示"你拒绝了这次运行" |
| `DEEP_REQUIRED` | 净室拒绝 | 页签显示深度占位 |
| `ENGINE_MISSING` | 外部引擎没装 | 页签显示"去安装" |
| `READ_ONLY` | 新版本写入的项目 | 项目只读横幅 |
| `CANCELLED` | 操作被取消 | 静默或轻提示 |
| `IO` | 文件读写 | 通知 |

### 1.2 责任边界

- **最终记录者**：
  - 界面发起的操作，错误在 `state::run` 的完成回调里记一次；
  - 复刻运行的错误由 `run/mod.rs` 的收尾记一次；
  - 分析通道里的工具错误由 MCP 作为 `isError` 结果返回给 Agent，宿主只记 `debug`。
- **跨线程 span**：
  - 复刻运行线程从 `RebuildService::start` 的 span 派生，构建方会话的读线程继承运行的 span；
  - 每条管道连接一个 span（`channel.session`），连接里每个 `tools/call` 是一个子操作 `channel.call`。
- **panic**：复刻运行仅用 `catch_unwind` 完成会话与 hold 清理，随后 `resume_unwind`；不把程序错误包装为可继续的 NeedsYou。日志 hook 同步落盘，异常退出遗留状态下次打开时修正。分析工具自己的隔离边界不扩展为宿主吞 panic。

## 2. 日志

事件名（`tracing` 的 message 字段）：

| 事件 | 级别 | 字段 | 禁止字段 |
|---|---|---|---|
| `analysis.engine.loaded` / `released` | info | project_id、holders | 路径之外的项目内容 |
| `analysis.call` | info（完成）/ warn（失败）| tool、caller、ms、code | 参数、结果 |
| `analysis.mode.changed` | info | project_id、mode | — |
| `channel.session` | info | chat_id、project_id、purpose、backend | 令牌 |
| `channel.call` | debug | tool、ms、is_error | 参数、结果 |
| `channel.long_tool` | info | tool、job、ms | 参数、结果 |
| `rebuild.run.started` / `finished` | info | project_id、backend、deep、message_kind（new/follow_up/continue）| 请求文字 |
| `rebuild.step` | info | step、round | 说明文字 |
| `rebuild.check` | info | check、round、passed、similarity | 截图路径之外的内容 |
| `rebuild.approval` | info | kind、outcome（allow/refuse/ask）、remembered | 命令文字、文件路径 |
| `rebuild.turn.retry` | warn | tries、wait_s、code | 错误正文 |
| `inbox.request` / `answered` / `withdrawn` | info | project_id、kind | 标题、正文 |

- 项目路径属于用户绝对路径，日志只写 `project_id` 的哈希前 8 位（`sha256(project_id)[..8]`）。
- 活动日志 `build-activity.log` 是给用户看的项目内记录（见[复刻编排](05-复刻编排.md)），不是诊断日志，密钥打码。

### 3.2 必须覆盖的行为

| crate | 测试 |
|---|---|
| core | `ChatScope` / `AnalysisAccess` 的 `Debug` 不含令牌；`AgentAction` 序列化稳定 |
| bridge | 未知令牌立即断开；撤销后下一次读入断开；64 条连接上限；双向透传字节一致（含服务端主动发出的通知）；超长行被拒 |
| analysis | 同一项目两次 `open` 共用一个 Engine；有持有者时 `close` 返回 `BUSY`；`view` 拿不到锁时返回 `stale` 且不阻塞；错误映射表逐项；只读会话调用有副作用的工具得到 `isError`、无副作用的工具正常；`core_person_ask` 等待回答期间，同一项目的另一个工具调用能完成，且两个工具的响应与 MCP 逐字节一致；`core_action_approve` 只有一个文本块；`set_mode` 后 session 的 `clean_room()` 改变；`LookInside` 默认深度、其他默认净室 |
| agents | 三个引擎的投影文件：服务器名 `autocraft`、`mcp-host` 参数、环境变量名、OMP `mcp.json` 只动 `autocraft-` 键、DSH `mcpServers` 带绝对路径与 env 列表；权限请求翻译表逐项；构建方会话里权限请求不产生交互卡；只读会话的启动参数 |
| settings | `project_prefs` 读写、revision 冲突、提供方删除后 `model_provider` 置空、项目复制与删除；`asset_keys` 掩码 |
| routing | 项目选择的模型填进 `RouteRequest.model` 后的 `prepare` 结果；不可路由时 `INVALID` 且原因来自 `model_status` |
| rebuild | 状态机：首次研究、同模式继续、换模式重新研究、换 Agent 不沿用会话、`NOT_WORKING_CHECK_LIMIT`、`max_rounds`、连续两轮无改动停止、补充说明打断检查回到构建、深度反编译提醒只发一次；审批：`approve_with` 的结果到 `PolicyVerdict` 的映射、取消时拒绝；补充说明：steer 成功即标记已读、不支持 steer 时本轮后发送、撤回只对未读有效；只是问问：问题长度边界、10 分钟超时；`rebuild_check` 自查队列（没有运行、等待超时、停止时的回答）；feed 映射；运行收尾的状态 |
| app | 主区域路由三个分支；切换项目恢复上次视图；`Fill` 各状态的渲染（不测文字）；审批卡回答写入 inbox |

不测试：布局文字、转发副本、默认值本身。

### 3.3 真实进程冒烟（`#[ignore]`）

隔离 `--data-dir`、隔离引擎配置目录、本机回环 SSE 上游，不用真实凭据。引擎可执行文件路径由环境变量 `AUTOCRAFT_SMOKE_PI` / `AUTOCRAFT_SMOKE_OMP` / `AUTOCRAFT_SMOKE_DSH` 指定（`crates/agents/tests` 的 `probe_*`，`cargo test -p autocraft-agents smoke:: -- --ignored --test-threads=1`）；端到端冒烟用 `AUTOCRAFT_T26_SPEC` 指向 JSON 启动配置，运行 `crates/app/tests` 的 `analysis_smoke` / `rebuild_smoke` / `mode_consent_smoke`（`-- --ignored`）；终端生命周期用 `autocraft-terminal` 的 `windows_pty_lifecycle_smoke`。

| 场景 | 断言 |
|---|---|
| 三个引擎各自启动，分析通道握手 | `tools/list` 返回 core 工具 + 两个元工具；服务器名 `autocraft` |
| 三个引擎各自让模型（回环上游脚本化回复）调用 `core_target_open` + `core_target_triage` 打开样本 PE | 返回证据 id；`AnalysisView.ledger` 出现该 id |
| `enable_toolset native` 后调用 `native_functions_list` | 成功 |
| DSH 调用一个耗时 > 60 秒的工具 | 立即得到"已开始"；之后收到结果消息 |
| 需要执行确认的工具 | inbox 出现审批卡；允许后工具执行，拒绝后返回 `consent_required` |
| 构建方会话：模型写 `app/` 内文件、写 `app/` 外文件、执行 `git push` | 内部放行；外部按 Auto 模式放行；push 在 Auto 模式下拒绝，原因回到模型 |
| 审批策略设为"询问"，构建方等待审批卡期间，界面在同一项目打开函数列表 | 函数列表正常返回，不被审批等待挡住 |
| pi 构建方运行中 `steer` | 模型下一步读到说明 |
| 一次完整复刻：无目标的静态网站请求 | 研究跳过 → 构建 → `build` 检查通过 → `Ready`；`craft.json` 能被 CLI `project_show` 读取 |
